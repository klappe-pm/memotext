# explanation

Explanation pages give the reasoning behind the code: how the pieces fit and why. They are for a contributor who wants to understand voicememos before changing it, and they are the right place to read when a change you are planning touches a design choice the user-facing [design](../../docs/explanation/design.md) page already records.

## pages

- [architecture](architecture.md): how a library folder becomes a list of recordings, layer by layer, and where each kind of failure is handled.
