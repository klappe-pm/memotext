# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added

- Package scaffold: `pyproject.toml` with the hatchling build backend, no runtime dependencies and the `memotext` console script.
- Library discovery, layer 1: `probe_library` and `probe_path` report each known path as `missing`, `readable`, `blocked` or `empty`, so a folder that exists but cannot be listed is never reported as found. `find_library` returns only a readable folder.
- Library discovery, layer 2: `spotlight_search` asks `mdfind` for candidate folders. It runs only on macOS and only when `find_library` is called with `spotlight=True` or a command is given `--spotlight`.
- `Recording`, `iter_recordings`, `read_transcript` and `content_hash`, with a standard library reader for the MP4 boxes that carry the duration (`mvhd`) and the iOS transcript (`tsrp`), and for the transcript in a `.composition` folder's `manifest.plist`.
- The `memotext` command with `probe`, `list` and `show`, each with `--json`.
- Documentation in one `docs/` tree arranged by Diátaxis quadrant, for people who use Memotext and for people who change it, including an explanation of where macOS keeps Voice Memos and why Full Disk Access matters, and a reference for the `tsrp` and plist formats that marks what is inferred.
- Repository documents: `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`, `CODE_OF_CONDUCT.md`, issue templates for a bug report, a feature request and a question, and a pull request template.
- Hardening against hostile files, with regression tests in `tests/test_hardening.py`: every file is opened without following symlinks or blocking on a FIFO; MP4 walking is lazy and bounded (10,000 boxes, 8 levels, a 64 MiB and 1,000 hit cap on the byte scan); the manifest search is iterative with a depth limit of 32 and a budget of 100,000 values, and visits shared values once; non finite and oversized durations are ignored and JSON output forbids NaN; dates outside the supported range no longer raise; a recording that cannot be read is skipped with a warning instead of aborting the run; text from files is escaped before it reaches a terminal; `list` keeps no transcript text; `mdfind` is called by absolute path. The [Security Model](docs/explanation/security-model.md) states each limit.
- A file system fallback for the recording date that reads `st_birthtime` with `getattr` and falls back to the modification time, because the attribute exists on macOS but not on Linux.

### Changed

- The documentation is one tree under `docs/`. The contributor pages moved there from `developer-docs/`, `release.md` is now `cut-a-release.md` and `api.md` is now `python-api.md`. Headings use Title Case, and the community files have uppercase names: `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md` and `SUPPORT.md`.
- The README follows the Stratarc layout: a banner, a badge row, a navigation row, a table of what changes with Memotext, and sections in a fixed order. Every link in it is absolute so that it works on PyPI.
- The `test` extra requires `pytest>=9.0.3` and `pytest-cov>=7`. Pytest releases before 9.0.3 carry CVE-2025-71176, and Pygments releases before 2.20.0, which pytest pulls in, carry CVE-2026-4539. The extras are exactly `test` and `lint`.
- The build requirement is `hatchling>=1.27,<2`, the sdist includes only anchored paths, and the metadata gains keywords, trove classifiers (Alpha, macOS and Linux, Python 3.11 to 3.13, typed), and the Homepage, Documentation, Changelog and Issues URLs.
- Ruff checks the rule sets E, F, I, UP, B, SIM, W, S and RUF.
- The release workflow is three jobs. Build installs only hash pinned tools, checks that the tagged commit is on `main` and that the tag matches the version, and writes checksums to the job summary. Test installs hash pinned tools and the built wheel and runs the suite against it. Publish needs both and is the only job that can request an identity token. Every action is pinned to a full commit of its current major release, and the lock files in `requirements/` are generated with `pip-compile --generate-hashes`.

### Fixed

- A hostile `manifest.plist` that made `plistlib` raise an `AttributeError`, `IndexError` or `LookupError` no longer aborts `list` and `show` with a traceback. `read_manifest` treats such a file as having no manifest, and `iter_recordings` skips a recording whose parsing raises any unexpected exception and reports it through `on_skip`.
- Terminal escaping now covers every character in the Unicode categories `Cf`, `Zl` and `Zp`, plus the combining grapheme joiner, the Hangul fillers, the variation selectors and the whole tag block U+E0000 to U+E007F. A title could previously smuggle hidden text, spelled in tag characters, into any program that read `show` output. Characters above U+FFFF are written `\UNNNNNNNN`.
- The default `RecordingSkippedWarning` message now escapes the file name and the reason, so an ESC or a right-to-left override in a file name no longer reaches standard error.
- A `.composition` folder swapped for a symlink between the directory check and the open is no longer followed. `read_manifest` opens the folder with `O_DIRECTORY` and `O_NOFOLLOW` and the manifest relative to that descriptor, so nothing outside the library is read.
- `content_hash` no longer recurses without bound. It walks the composition folder iteratively from a descriptor, refuses a folder swapped for a symlink during the walk, raises the new `CompositionLimitError` for a folder nested more than 64 levels deep or holding more than 100,000 entries, and raises when a subfolder cannot be listed instead of leaving it out of the digest.
- The `--spotlight` fallback no longer adopts any folder whose path contains "VoiceMemos". `find_library` accepts a Spotlight candidate only when it lies inside a known Voice Memos container under `~/Library`. `list` and `show` print which folder was chosen and that Spotlight chose it on standard error, and `probe` reports `library_source` in its JSON output and a note in its text output.
- The command line no longer raises `UnicodeEncodeError` when standard output or standard error cannot encode a character in a title or file name, for example under `PYTHONIOENCODING=ascii`. Both streams are switched to `backslashreplace` at the start of `main`.
- `list` no longer decodes the transcript payload it discards. With `transcripts=False`, `iter_recordings` detects the source from the presence of a non empty `tsrp` box and never calls the JSON decoder. `show` now reports the source it actually decoded.
- `list` and the ambiguous id error of `show` print ids that differ only in Unicode normalisation (NFC against NFD) as `ascii()` literals, so look-alike ids can be told apart.
- `--json` output is now valid for a strict decoder. A lone surrogate from a file name that is not UTF-8, or from a transcript, is replaced by U+FFFD, and a recording whose id was not valid UTF-8 carries a new `id_bytes_hex` field with the raw bytes of the id.
- `content_hash` no longer leaks the descriptor of the composition folder when listing that folder fails. The root is closed on any exception before the error is raised.
- `content_hash` no longer raises `UnicodeEncodeError` for a file name inside the composition folder that is not valid UTF-8. The name is encoded back to its original bytes, so two such names give different digests, and the digest of every valid name is unchanged.
- A `.composition` folder with search permission only (mode `0311`) no longer causes its recording to be skipped. When opening the folder fails with `EACCES`, `read_manifest` opens `manifest.plist` by path with `O_NOFOLLOW`. The descriptor based open, and its protection against a swapped folder, is unchanged for a folder that can be opened.
- Terminal escaping now covers every code point with the Unicode property `Default_Ignorable_Code_Point` (the Khmer vowels U+17B4 and U+17B5, U+180F, U+2065, U+FFF0 to U+FFF8, U+1BCA0 to U+1BCA3, U+1D173 to U+1D17A and the whole range U+E0000 to U+E0FFF were missed), every code point in the categories `Cn` (unassigned) and `Co` (private use), and the 66 noncharacters. The ranges are written out from Unicode 15.0 because `unicodedata` does not expose the property.
- Terminal escaping no longer breaks emoji. The variation selectors U+FE0E and U+FE0F are kept straight after an emoji character (or after a digit, `#` or `*` followed by a keycap), and the zero width joiner U+200D is kept between two emoji characters, so `❤️` and `👨‍👩‍👧` print unchanged. A selector or joiner that is leading, trailing, repeated, or beside a character that is not an emoji is still escaped, and every other variation selector is always escaped. `printable` also decides once per distinct character and rewrites the text in one pass: escaping 11 million CJK characters takes 0.44 seconds, against 2.8 seconds before the invisible character fixes and 4.0 seconds after them.
- `list` and the ambiguous id error of `show` now group look-alike ids by the form they print in, which is the id in Unicode form NFC passed through `printable`. Two names that are not valid UTF-8 and differ only in the bad byte both print with a question mark, so they are now shown as `ascii()` literals and can be told apart.
- `list` and the ambiguous id error of `show` group ids that differ only by a space separator among the look-alikes: `memo` against `memo` with a trailing space, a no-break space or an ideographic space, and `my memo` against `my` and `memo` with a no-break space or a figure space between them. Both ids of such a pair printed as the same text because spaces are not escaped. The grouping key now reads every space as a plain space and drops trailing space, and each id of a pair is shown as an `ascii()` literal.
- `UnsafeFileError` and `RecordingSkippedWarning` are exported from the top level and listed in `__all__`, as the Errors table of the Python API reference already implied. The warning row of that table now says it is issued for any exception other than `MemoryError` that stops a recording being read, and only when no `on_skip` callback is given.
- `memotext list | head -1` no longer prints `memotext: [Errno 32] Broken pipe` or an `Exception ignored` message. `main` flushes standard output inside its handler, points standard output at the null device when the reader has closed the pipe, prints nothing, and returns 141 (128 plus `SIGPIPE`), the pattern the Python documentation recommends.
- Terminal escaping now covers the braille pattern blank U+2800 and the musical symbol null notehead U+1D159, which draw as blank although they are not default ignorable, so a recording named `memo` and one named `memo` followed by U+2800 no longer print the same. The Hangul fillers U+115F, U+1160, U+3164 and U+FFA0 were already escaped. The README now lists exactly the kinds of character that are escaped.
